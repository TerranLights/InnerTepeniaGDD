# [City] change over time — Conflict-Driven Variant
### Featuring [Character A] and [Character B] (placeholder figures — unnamed, per turning point)

**Companion file to `z-template_-_city_histories.md`, not a replacement for it.** That template
tracks one featured Doll's personal response across a city's whole post-settlement history. This
one instead drives each turning point through two unnamed placeholder characters coming into
conflict, with the specific outcome of that conflict — not the abstract circumstance behind it —
producing the 2nd- and 3rd-order changes that become the next State of Affairs. A single city's
actual history file may mix cycles from both templates: some turning points are better told through
one character's felt experience, others through two people's collision. Use whichever shape a given
cycle actually needs.

Same underlying But/Therefore grammar as the original template (see
`But_Therefore_Lore_Design_Method.md`) and the same starting assumption established for this whole
line of work: early settlement/founding is already done and out of scope here. Every cycle below
starts from an already-settled city.

---

## Basic Structure:

- [STATE OF AFFAIRS N] — the baseline, as things stand going into this cycle.
- [TRIGGER], then time passes. // But — something disrupts the baseline
- [CHARACTER A] and [CHARACTER B] come into conflict.
- [CULMINATION] — their conflict reaches its outcome. // Therefore — a specific, concrete resolution
- [2ND-ORDER CHANGE], caused directly by that outcome. // Therefore
- [3RD-ORDER CHANGE], caused by the 2nd-order change — not by the conflict itself. // Therefore, once removed
- Time passes.
- [STATE OF AFFAIRS N+1] — the new baseline, feeding the next cycle.

###### (repeat as necessary — a new, different, unnamed pair of characters each cycle)
