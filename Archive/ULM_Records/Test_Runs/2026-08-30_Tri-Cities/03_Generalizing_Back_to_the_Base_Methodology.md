# Generalizing Back — What This Run Means for the Base Methodology

**The most important file in this test run.** The three city passes are the material; the observations file is
the instrument reading; **this file is the correction to the instrument.**

> **⚠ THE CORRECTION THAT REFRAMES EVERYTHING BELOW** *(developer instruction, 2026-08-30, mid-run)*
>
> **The methodology's fundamental unit is ONE location, start to finish.** In the overwhelming majority of
> instances it will build a single individual location and nothing else. **Multi-location capability is a
> possible extra, never the base structure.**
>
> **This test run violated that assumption throughout, and did not notice until told.**

---

# 1. What this run got structurally wrong

**The Tri-Cities run was written as a simultaneous three-location co-write.** `01_Phase0_Frame_and_Phase1_Capability.md`
opens by saying so explicitly — *"written together for all three cities."* **Every headline finding depends on
that.**

**There is a rule permitting it** — `01` §5.3's *"set of two → write them together,"* the Virgo/Pisces pairing
rule, arguably extending to a designed three. **But a permission for an exceptional case is not a template**,
and running the first-ever test of the methodology on its most exceptional configuration produced a validation
that does not transfer.

### The specific self-flattery this created

**The Tri-Cities are the highest-relationality location set in the entire project:**

| | Tri-Cities | A typical Tepenian city |
|---|---|---|
| Distance to nearest peer | **0.3–8 km** | 100–600 km |
| Shared founding act | **yes, one court ruling** | no |
| Shared airport | **yes** | no |
| Shared population trio | **yes, all three tiers** | no |
| Pre-existing differentiation instrument | **yes** | no |

> **Phase 5 produced seven findings here. That is a best case, not a measurement.** Reporting it as evidence
> that the restored phase works would repeat the exact failure the README names against the district folder —
> *"eighteen consecutive prediction confirmations came from a self-grader."* **The remedy the district folder
> flagged three times and never applied is to run the case chosen *because* it looks least likely to conform.**
> **Vostok, Kunlun, Dome Fuji and Amundsen Station are that case, and none of them has been run.**

# 2. The architectural finding: the no-sibling path is the default, not the fallback

**`01` §5.3 presents four situations — large set, small set, set of two, and "no siblings" — and treats the
last as the edge case needing substitutes.** The developer's correction inverts this.

> **PROPOSED — restructure `01` §5.3 so that the single-location path is the primary procedure, and sibling
> comparison is an *enhancement available when siblings exist*.** The current ordering teaches a reader that
> comparison is normal and isolation is a problem. **The opposite is true in practice.**

**This is not a wording change.** It changes which instruments the methodology presents as core:

| Instrument | Needs siblings? | Status under the correction |
|---|---|---|
| **The four-quadrant capability frame** | **No** | **Core** |
| **The generator stack + rule of three** | **No** | **Core** — and this is why three generators matters more than it appeared |
| **The deficit *address* axis** (`02` §4.1) | **Mostly no** | **Core** — see §3 below |
| **Shape typology** (`02` §4) | No *(reading)* / yes *(the three-step repeat rule)* | **Core, with a sibling-only sub-rule** |
| **Pairing-relation typology** (`02` §6.3) | **No** | **Core** |
| **Named-axis discipline** | No | Core |
| **The differentiation table** (`04` Part III) | **Yes** | **Enhancement** |
| **Phase 5b three-way set** | **Yes** | **Enhancement, needs a substitute** |
| **Gate 6 collision check** | **Yes** | **Enhancement** |

**The good news, and it is genuine:** **most of the methodology is already single-location-safe.** The
generator/capability/address machinery — the actual spine — never needed a sibling. **Only the anti-convergence
layer does**, and that layer is correctly understood as a *guard* rather than a *generator*.

# 3. The deficit-address axis is the single-location substitute for differentiation

**This run's most transferable discovery, and it was not the intended one.**

**`02` §4.1's address types split cleanly into two groups:**

| Address type | Requires a named peer? |
|---|---|
| Diffuse · In its own past · In the parent · Nowhere at all | **No** |
| Single address · Multiply addressed · Reciprocal · Across an antagonism · *adjacent but unaskable* | Yes |

> **The peer-free half is a complete instrument on its own.** A location with no siblings can still ask *where
> does the thing that would fix this live?* and get **"in its own past," "in the parent," or "diffuse"** — and
> each of those produces a different, specific, non-generic culture. **Shirayuki's strongest finding used "in
> its own past," which needs no sibling at all.**

**PROPOSED addition to `02` §4.1:** mark each address type as **peer-required** or **peer-free**, and state
that **a single-location pass runs the peer-free set first** and only reaches for the peer-required ones if
canon actually supplies a named counterparty.

# 4. Phase 5, rebuilt for one location

**Phase 5 as written assumes neighbors worth writing about.** Tested against the isolated majority case it is
**four-fifths sound and one-fifth sibling-dependent** — better than expected, but the weighting is wrong.

### What transfers unchanged to a single isolated location

- **5a's core move — *mechanism, not rivalry*.** Works against a supplier, a parent, an absent peer, or a
  category. **Never needed a neighbor; needed a counterparty.**
- **"Write both directions."** For an isolated location the second direction is frequently ***nobody out there
  thinks about this place at all*** — **which is a finding, not a blank.** A location that matters to itself
  and to nobody else is a specific and common condition.
- **5c the parent** — and for isolated locations **this is the primary relation**, not one of five.
- **5d the edge and the crossing** — who arrives, what they meet first, what converts a visitor to a member.
  **Entirely peer-free and among the most productive questions in the file.**
- **5e dependency, named vs unnamed → politics vs shadow.** **Peer-free, and one of the best single-location
  instruments the methodology has.** It produced three findings here without needing the cluster.

### What does NOT transfer, and the substitute

**5b — the three-way differentiation set — requires two peers and has no meaning without them.**

> **PROPOSED substitute for the single-location case, drawn from `01` §5.3's existing no-sibling list rather
> than invented:**
> **Run the three-way set against the location's own eras instead of against neighbors.**
> *This place at founding · this place at its crisis · this place now* — **three states of one location, on one
> chosen category, differentiated the same way.** `01` §5.3 already calls a location's own earlier states *"the
> strongest substitute and usually available."* **Phase 5b is where that substitute should be named
> explicitly**, because a reader reaching 5b with no siblings currently has nowhere to go.

### PROPOSED reweighting of Phase 5 by situation

| | Isolated location *(the majority)* | Clustered location *(rare)* |
|---|---|---|
| **5a** Peers | **optional** — often a category, not a name | mandatory |
| **5b** Three-way set | **→ substitute: own eras** | mandatory |
| **5c** Parent | **PRIMARY** | mandatory |
| **5d** Edge & crossing | mandatory | mandatory |
| **5e** Dependency | **PRIMARY** | mandatory |

# 5. What genuinely transfers from this run to any single location

**Stated separately from the Tri-Cities material, so it is usable without them.** Each was *discovered* through
the cluster but does not *depend* on it.

1. **Score any quantitative differentiator against the full population, never the local group.** The retention
   finding only became meaningful at z = −1.26 against 33 cities; the human/robot finding died at z = ±0.4.
   **A single-location pass needs this more, not less** — with no siblings to sanity-check against, an
   uncontextualized number is the easiest way to manufacture a false distinctive.
2. **A location's census history is an unread generator.** Retention across two censuses was available for
   every city in the project and used by none. **Peer-free, arithmetic, and it produced this run's strongest
   finding.** *(PROPOSED: add "population change across available snapshots" to G8's read instructions.)*
3. **Pull and push differ in durability.** Ask of any location built on attraction: *what happens when
   somewhere more attractive opens?* **Peer-free.**
4. **Check whether a deficit's witnesses are still present.** Where the people who could name the problem are
   the people who left, the location cannot diagnose itself. **Peer-free, and it generalizes far past
   Shirayuki** — it applies to any Declining or post-exodus location.
5. **A dependency nobody has named is a shadow; a named one is politics** — and **a loudly-named minor
   dependency can conceal an unnamed major one.** *(Sinheung talks constantly about where its materials come
   from and never about where its designs come from.)* **Peer-free and highly portable.**
6. **Read registered symbols from the file, never from familiarity with the name.** Saturn inverted this run's
   entire Zhongshan reading. **Peer-free.**
7. **Verify a computed figure by hand-checking one row against the source** — plausible wrong numbers are more
   dangerous than zeros. **Peer-free.**

# 6. What remains genuinely cluster-specific and must not be generalized

**Recorded so a later reader does not mistake these for portable technique.**

- **The "adjacent but unaskable" address type.** Real, and it needs a neighbor close enough to see and a norm
  forbidding the asking. **Keep it as a peer-required address; do not present it as common.**
- **R-2's reciprocal-and-unaskable pair** and **R-3's same-symbol-different-stage pair.** Both require siblings
  with known profiles. **Genuine findings; not templates.**
- **The shared-symbol collision analysis.** Requires two locations drawing the same symbol — possible only
  where a symbol system is exhausted against a large location set.
- **TC-1, the regional "each is blind by a different mechanism" finding.** **This is the best thing the run
  produced and it is the least portable.** It required three complete profiles simultaneously.

# 8. The honest verdict on this test

**What was actually validated:** the declaration block *(caught a real frame error)*, the pairing-relation
typology *(produced a finding canon lacked)*, the "in its own past" address *(fired on its first eligible
case)*, the both-are-true test, the shape typology, and the verification disciplines *(caught three of my own
errors)*. **All of these are peer-free and therefore genuinely transfer.**

**What was NOT validated, and must not be claimed:** **Phase 5 in the isolated case** · the differentiation
instrument under normal conditions · **any of the eleven phases except 0, 1 and 5** · every gate · the Review
Panel · and the methodology's behavior when canon is *thin* rather than abundant. **This run had ~12,000
lines of input. The majority case will have a spec sheet and a map.**

> **The next test should be a single isolated location with sparse canon** — the inverse of this one on both
> axes. **Vostok, Kunlun, Dome Fuji, or Amundsen Station.** Run it start-to-finish, alone, and **state the
> falsification criteria in advance**, which the district folder flagged three times and never did.
