# DLC City Under-Questline Design Method — Input Synthesis & But/Therefore Construction

**What this is:** the method for constructing per-DLC-city "under-questlines" — non-main, naturally
discoverable content within a single DLC city, the direct analog of `Storyline/Side-Content/
District_Under_Questline_Design_Method.md` at the DLC-city level. That file was itself adapted from
`DLC_Main_Questline_Design_Method.md` (this same folder); this file is a second-generation adaptation —
DLC-city plays the "district" role, and the whole DLC subnet plays the "Concordia" role a district method
gave to the whole capital city. Distinct from `DLC_Main_Questline_Design_Method.md`, which governs each
subnet's own single capstone main questline; this method produces everything else naturally discoverable
within one DLC city, plural, non-load-bearing for any ending condition.

**Where this sits** (same calibration the district method uses, since the distinction is universal, not
district-specific):
- **DLC main questline** (`DLC_Main_Questline_Design_Method.md`) ≈ the subnet's own central, given
  assignment — Manny Vargas sending the player to RepCONN, scaled to DLC size.
- **DLC city under-questline** (this method) ≈ No-Bark Noonan mentioning Dusty McBride's brahmin being
  shot nightly, or Boone's "One for My Baby" — something the player runs into through ordinary
  conversation or exploration inside a specific DLC city, not a formal assignment.
- **True side-content** (out of scope here) ≈ The Witcher 3's "Frying Pan" — no organic lead-in, found
  only by a player actively hunting for it. Nothing in this project currently designs for that tier.

**Starting-point rule, identical to the district method:** every candidate must anchor to either a
**named in-world figure** local to the city (not a headline character) or a **data-point at a significant
location** the player can actually run into through ordinary play. Notable Figures are therefore included
as an input (see input 4), the same deliberate departure from the DLC Main Questline method's own rule.

## Step 1: Gather Inputs

For the specific DLC city under construction, pull the following — same "distilled findings, not the
whole document" discipline both parent methods use:

1. **The city's own Cross-Reference Synthesis** (`[City]_Cross_Reference_Synthesis.md`) — only each
   Finding's bolded **4th-order effect:** line, plus the closing **Synthesis** section.

2. **The subnet's own Cross-Reference Synthesis** (`[Subnet]_Subnet_Cross_Reference_Synthesis.md`, in the
   subnet's own `[Subnet]_Subnet_Ultra_Megasheet/` folder) — same rule: 4th-order-effect lines and the
   Synthesis section only. **For single-city subnets (Byrd), no separate subnet-level file exists by
   design** — `Byrd_Mega_Init.md` itself explains why: a single city carrying a full DLC alone was built
   with extra depth specifically to absorb the work an Ultra-Megasheet layer does elsewhere. Use the
   city's own Cross-Reference Synthesis (input 1) to cover this input too in that case.

3. **The subnet's own Cross-City Throughways, in full** (`[Subnet]_Cross_City_Throughways.md`) — take the
   full resultant finding of each Throughway that touches this city, not just a single line. **N/A for
   single-city subnets** — there's no second city to throughway to.

4. **The city's own Full Extrapolation**, every section **including Notable Figures** (Demonym excluded,
   same rule as both parent methods).

5. **The city's own stated civic identity/character** — for multi-city subnets, this is the subnet's own
   `[Subnet]_Subnet_Full_Extrapolation.md` §I entry for this specific city (its role within the subnet's
   collective theme). For single-city subnets, or where no such entry exists, use the city's own Local
   Cultures "What It Feels Like" / "One-Line Pitch" material, or the equivalent core-identity statement in
   its own Full Extrapolation or Mega-Init. **Pin down the exact citation once per city rather than
   assuming a uniform location** — this is the single most load-bearing input, the same status it holds in
   both parent methods, and it's worth getting the citation right before treating it as settled.

6. **DLC Main Questline Candidates for this city's own subnet** (`Storyline/DLC-Questlines/[Subnet]/`) —
   **chosen substitute for the district method's own "Questlines layer" input**, confirmed 2026-07-30.
   Unlike Concordia's districts, DLC cities have no pre-built Questlines layer, but the Main Questline
   candidate pool already exists in almost the same shape: cause, escalation, a genuine fork, real
   trade-offs on every branch, built with the same But/Therefore method. Filter to candidates that
   genuinely center this specific city (for single-city subnets like Byrd, every candidate qualifies
   automatically; for multi-city subnets, check each candidate's own "Uses N of [Subnet]'s M cities" note
   and keep only the ones naming this city). Treat a qualifying candidate — chosen, set aside in a
   `recycling-bin/`, or still unranked — as a strong seed to build an under-questline from or refine, the
   same instruction the district method gives its own input 6. **A set-aside "recycling-bin" candidate is
   an especially strong source**: it was ruled out for main-questline reasons unrelated to its own
   construction quality (see `Byrd`'s own Chamber Crisis draft, set aside for the Cradle-unmarked-lore
   design law, not for being poorly built) — already a complete, well-formed chain looking for a home.

7. **The city's own Local Cultures sheet** (`Local_Cultures/[Subnet]/[City].md`) — exists as a genuine
   separate file for every DLC city, cleaner here than the district version, which had to be extracted
   from inside a Megasheet.

8. **The Super-Ultra-Megasheet**, wherever it touches this subnet or city — same role it plays in both
   parent methods.

9. **The city's own Physical Infrastructure Attributes/Findings file, full text** — **chosen substitute
   for the district method's own Non-Malice Audit input, confirmed 2026-07-30.** Each Finding is already
   structured as "Combining [specific facts] → 2nd-order → 3rd-order → 4th-order effect" — the same
   escalating-consequence, named-artifact shape the Non-Malice Audit files use for districts. Treat the
   concrete attributes and Findings inside it (a named location, a specific mechanism, a flagged tension)
   as strong starting-point candidates in their own right, the same instruction the district method gives.
   **Currently exists only for Byrd** (`Byrd_Physical_Infrastructure_Attributes.md`, 80 attributes/57
   Findings) — this session's own original deep-dive, not yet replicated for the other 5 DLC subnets.
   **Fallback where no such file exists yet:** re-read the city's own Cross-Reference Synthesis (input 1)
   in full — not just the trimmed 4th-order-effect lines input 1 itself uses — since the same "Combining →
   2nd/3rd/4th-order" shape is already present there, just not yet extracted at the same density a
   dedicated deep-dive would produce.

10. **The city's own "Community Infrastructure & Social Life" file** (`[City]_Community_Infrastructure.md`)
    — the Additions, Small offices, and Social cohesion mechanisms. **Now exists for all 35 DLC subnet
    cities**, completed 2026-07-30 — this is exactly what unblocked this whole method. Treat every named
    item as a candidate anchor worth checking, the same instruction that made this the district method's
    own most valuable late addition.

## Step 2: Construct Candidate Chains

Using everything gathered in Step 1, construct candidate But/Therefore chains for this city's own
under-questlines (per `But_Therefore_Quest_Design_Method.md`). Same floor as the district method: **at
least 5 per city, ideally 15-20**, and **candidates are not narrowed down** — every candidate that passes
the tests below is kept as real content.

Each candidate must satisfy:

- **Anchored to a starting point.** Name the specific figure or location/data-point (from input 4, 7, or
  10) the candidate actually starts from. If a candidate can't point to one, it isn't a natural
  under-questline yet.
- **Non-conflicting.** Doesn't contradict anything gathered in Step 1.
- **Characteristically consistent.** Reads as something that could only happen in *this* DLC city
  specifically — grounded in its own stated civic identity (input 5) and its own established population,
  character, and (where applicable) subnet relationships (inputs 4, 6, 7).
- **Actually emergent, not invented.** Traces back to a specific 4th-order effect, Main Questline candidate,
  Physical Infrastructure Finding, or Full Extrapolation section — not a new idea dropped on top of the
  source material.

**Plus the same belief-consequence default the district method confirmed** (`feedback_district_belief_
consequence_default` memory), adapted to DLC-city scale: default to **"can this city handle the results of
its own established character," not "is this city's character actually right, fair, or true."** Every DLC
city already has a sincere, established civic identity (input 5) or physical/cultural character (inputs 9,
10) — write the city as consistently acting on it, testing whether *living inside* that character remains
sustainable under real pressure, not building toward the revelation that the character itself was wrong.

**Cross-city candidates are allowed** for multi-city subnets, the same way the district method allows
cross-district candidates — an under-questline reaching from one DLC city into a subnet neighbor should be
treated as a normal shape, not an exception, especially where input 6's own Main Questline candidates
already establish that kind of cross-city material exists in the subnet.

## Worth Your Attention

This method is untested — written 2026-07-30, directly following the same-day completion of input 10
(Community Infrastructure for all 35 DLC cities) and a working session that produced input 9's own source
material for Byrd specifically. **Byrd is the only DLC city where every single input in Step 1 currently
has real, existing material behind it** — inputs 6 and 9 both resolve cleanly and richly there (28 Main
Questline candidates, 80 attributes/57 Findings). For the other 5 DLCs, input 9 has no dedicated file yet
and falls back to a closer re-read of each city's own Cross-Reference Synthesis, and input 6 needs each
Main Questline candidate checked for genuine per-city anchoring rather than assumed. Byrd is therefore the
strongest available first test case for this method, the same way Leo was the district method's own first
test — worth running there before trusting the method's own input-9 fallback or input-6 filtering logic
against a city that hasn't been through anything like this session's own deep-dive.
