# The Acquisition Paths

> **⚠ Read `00_RUNBOOK.md` first.** Only **LIVE** gaps (`01` §4.4) reach this file. **LAW B governs every path's
> output** — what you acquire determines what tier it must be deposited into (§1 below, then `03`).

---

# 1. The seven paths, and the two things to know before choosing one

**These are not invented for this system.** All seven are modes this project has already practiced — several of
them extensively, none of them formalized together until now. **Ordered cheapest-first, and the ordering is
itself the procedure: try cheaper paths before expensive ones, and record which cheaper ones you ruled out and
why.** *(Same shape as the "order of attempts" discipline the location methodology already uses for its
Inflected class — check what already exists before generating anything new.)*

| # | Path | Cost | Yield | **Characteristic output KIND** *(governs deposit, per `03`)* |
|---|---|---|---|---|
| **1** | **Cross-reference** | trivial | narrow but certain | **Attribute** |
| **2** | **Derivation** | low | narrow, exact, checkable | **Attribute** |
| **3** | **Withheld-file check** | low | can be large | **Whatever the withheld file already was** — usually conclusion |
| **4** | **Light real-world research** | medium | medium-high, often surprising | **Attribute** *(the fact)* + **conclusion** *(the fusion)* — split them |
| **5** | **Deep source extraction** | high | highest per item, slowest | **Attribute**, usually; occasionally a whole framework |
| **6** | **Developer ruling** *(batched)* | developer's time | exact, authoritative, unappealable | **Decision** |
| **7** | **Developer creative elicitation** | developer's time, richest | **highest in the project's whole history** | **Conclusion** |

> ### ⚠ The single most important row in that table is the last column.
>
> **The path you choose largely predicts the tier you must deposit into**, which is what makes LAW B
> operational rather than a case-by-case judgment call. **Paths 1, 2, and 5 produce attributes and are
> deposit-safe almost by construction. Path 7 produces conclusions and is the single most dangerous path in
> this system**, because it is also the most productive — it is the path that produced the Cape Adare
> deposit-chain failure (`00` LAW B), and it will keep producing exactly that kind of content, because that is
> what it is *for*.

# 2. Path 1 — Cross-reference

**The answer already exists in admissible project canon and has simply never been connected to this gap.**

**When it is right:** always try first. Costs one search.

**Procedure.**
1. Search the scope's own sibling set, then the shared/aggregate files, then repo-wide with no path restriction.
   *(The concentric-ring widening the project's own investigation skeleton already specifies — the outermost
   ring exists because a repo-wide unrestricted grep has repeatedly found things every narrower search missed.)*
2. **Read every hit. Never accept a grep count as the answer** — grep prioritizes; it never verifies.
3. **Check the found source's own admissibility before using it** (`05` §6.1, §6.1a–d). A found fact sitting
   inside a conclusion-bearing section is not an attribute just because you needed one.

**Failure modes, both recorded in this project:**
- **Copy-paste value migration.** Two entities sharing an identical templated block: the fact is correct for
  the entity it was copied *from* and wrong for the one it was copied *to*. **Matching wording is not evidence
  of independent verification.** *(Recorded: a founding-wave tag on the wrong nation, copied between two
  cities whose tier tables matched exactly.)*
- **"One of N" / "the only X" claims going stale** as siblings are added later. **Re-verify the count; never
  inherit it.**

# 3. Path 2 — Derivation

**Computable from facts already known, via a formula this project has already standardized.**

**When it is right:** the gap is quantitative, or follows mechanically from established figures.

**Established formulas available:** census share-weighting and de-stacking · retention across census snapshots
(Census II ÷ Census I) · population density (population ÷ extent) · proportional recalculation when a nation is
removed from a composition (factor = 100/(100−removed%)).

**Procedure.**
1. Name the formula and the inputs explicitly.
2. **Verify each input at its own source, not at a neighbor that agrees with it.** *(This is the shared-constant
   trap: a wrong era-length once sat in 20 files across 8 locations, and every file agreed with every other
   file, so consistency checking between them passed while all of them were wrong.)*
3. Compute, then **hand-check one row against the source table.** A plausible wrong number does not announce
   itself.
4. **Score comparative claims against the full set, never a local group** — report a z-score, not a difference.
   *(A human-vs-robot retention gap has been found and killed on exactly this basis more than once.)*

**Failure mode:** deriving something arithmetically correct and substantively meaningless. **A number is not a
finding.**

# 4. Path 3 — Withheld-file check

**The answer already exists, and was never missing — only quarantined from one specific pass.**

**When it is right:** the gap was emitted by a cold/anti-contamination pass (the location methodology's
signature case). The pass could not read the file; this system can.

**Procedure.**
1. **⚠ Confirm no pass on the SUBJECT is pending — not merely that the emitting pass finished.** *(Corrected
   2026-08-31, during this system's own readiness check, before any Path 3 acquisition was run. The original
   wording asked only whether "the consuming pass is genuinely finished," which is **the wrong scope** and
   would have passed a case that should have failed — see the worked hazard below.)* **Check for deferred
   phases, scheduled follow-up passes, and any successor run on the same subject.** Reading withheld material
   contaminates *every* future cold pass on that subject, not just the one that emitted the gap.
2. Open the withheld file **only for the specific question**, not as general reading.
3. **Deposit carefully: what you found was a conclusion when it was written, and it stays one** (`03`). Moving
   it does not convert it into an attribute.

**Failure mode, structural and important:** this path can make a cold pass's finding look wrong when it is
merely *different*. **Run the both-are-true test before recording any mismatch as a correction** — a
contradiction between a cold derivation and existing canon is very often a scale mismatch (public/private,
mainstream/counterculture, generational, legal-versus-narrative), not an error.

> ### ⚠ Worked hazard — caught by a readiness check, before any Path 3 run happened
>
> **CGRM-007 (Cape Adare's music/arts) was classified Path 3 and appeared on a recommended first-run list.**
> Its answer genuinely does sit in withheld material — ULM Run 7 deliberately declined to reconstruct it. Under
> the *original* step 1 wording, the check passed: **Run 7 is finished.**
>
> **It should have failed.** Run 7's own Phase 10 §G defers the **Zodiac Lens to "a dedicated follow-up pass on
> this same location."** That successor pass would want to run against the same quarantine — **so opening Cape
> Adare's withheld culture files now would contaminate a pass that has not happened yet.**
>
> **CGRM-007 is therefore BLOCKED, not available**, until Cape Adare's Zodiac Lens follow-up either runs or is
> formally abandoned. **The gap is real, the answer exists, and it must stay unread anyway** — which is LAW A
> in its least comfortable form: *an open gap is not a defect, even when you know exactly where the answer is.*

# 5. Path 4 — Light real-world research

**Web research on a real, specific comparable, fused against established in-fiction fact.**

**Governed entirely by `../Locations-and-Levels/Real-World_Basis_Extrapolation_Method.md`** — this system does
not restate that method, it calls it. **Three of its rules matter most here:**

- **Research the specific place, never the category.** *"An ancient Greek healing sanctuary"* yields nothing;
  *"Epidaurus"* yields the abaton's two-room structure and the inscribed cure-records.
- **Do not stop at the first usable result.** After each source, ask whether it named something else worth
  chasing — and log the unchased threads rather than losing them.
- **Source is not specification.** Divergence stated explicitly is stronger than resemblance implied.

**⚠ Binding constraint, non-negotiable: GPS facts only, always.** The rule lives at
**`/home/kuroskalacs/Documents/Doll-Fi/media/Reference/TepenianUniverseTimeline/Reference/No_National_Stereotypes.md`**
— **in the universe repo, OUTSIDE this one.** *(Cited here as a bare local-looking path in this file's first
draft, and caught by a readiness check: a repo-local search returns nothing for it, confidently and wrongly —
the exact trap this project has already recorded, where six escalating "repo-wide" clean passes each searched
a space that structurally could not contain what they were looking for. **Open it deliberately or you will not
open it at all.**)*

> **This is the path with a recorded, severe failure attached, and it is worth stating in full.** A city's
> attributes file asserted a continuous Korean cultural institution derived from its real-world station's
> naming nation — but the ~500-year First Interwar Period saw stations change national hands repeatedly, which
> rules out any such continuity. A second city's *entire founding narrative* rested on the same invalidated
> premise. **Both files were written after the project's own audit sweep had closed, so nothing caught them for
> weeks.** *(Two consequences follow: the constraint below, and Gate 4 in `04`.)*
>
> **The constraint: a real-world station's operator nationality is a GPS fact and never a cultural cause.** A
> location's own current population table is a legitimate cause; an essentialist national temperament never is.
> **Sort every nationality-touching research finding into those three buckets before using it.**

**Also check before searching:** `Reference/Real-World/City_and_District_Research_Topics.md` — a per-location
research wish-list already exists for all 13 districts and 36 cities/stations, and it is grounded in what is
already established about each. **The question you are about to research may already be on it, framed better.**

# 6. Path 5 — Deep source extraction

**Mining a real book or document set, rather than a web search.** Slowest path, highest per-item yield, and it
has real existing infrastructure: `Reference/Materials/books/` holds the sourced PDFs, and
`City_and_District_Research_Topics.md` maps which collections are earmarked for which location.

**When it is right:** the gap is conceptual or systemic rather than factual — it needs a *framework*, not a
number. **Not for closing a single small gap; the cost only justifies itself against a cluster.**

**Procedure.**
1. **Check `Reference/Real-World/Book_Extraction_Index.md` FIRST.** *(This index exists because a book was
   twice assessed as unmined when it had in fact already been mined in full.)*
2. Extract against a **specific question**, not "read the book." The project's own precedent is a dedicated
   extraction-checklist folder built only once there is a real question worth answering.
3. Record the extraction in the index so the next session inherits it.

# 7. Path 6 — Developer ruling *(batched)*

**For RESERVED items only. This system prepares; it never decides.**

**The value added here is not the decision — it is arriving at the decision with the work already done.**

> ### ⛔ MANDATORY BEFORE ROUTING ANYTHING: run the unrestricted repo-wide search
> **Added 2026-08-31, after this path failed exactly this way on its own first use (M-57).** A question was
> routed to the developer as RESERVED — and the answer had been **formally adopted six weeks earlier**, in a
> file outside the subject's own folder. The search had stayed inside the subject's file set.
>
> **`grep -rn "<subject>" .` with NO path restriction, and read the hits.** The concentric-ring rule this
> project already uses exists precisely because its outermost ring keeps finding what every narrower search
> missed. **The cost of skipping it here is not a missed fact — it is spending the developer's own authority on
> a question that was already closed, which is the single most expensive mistake this path can make.**

**A well-formed queue entry states five things**, and an entry missing them wastes the developer's time rather
than saving it:
1. **The question**, in one sentence.
2. **Why it is reserved** — whose authority, and why it cannot be researched or derived.
3. **The constraints** — what canon already fixes, so no option offered violates something established.
4. **Options, if there are natural ones**, each with its consequence stated. *(Not always applicable — a
   character's name has no shortlist unless the developer wants one.)*
5. **What is blocked**, and how badly — cannot-proceed, or proceeds-thinner.

**Batching rule:** accumulate; do not interrupt. **A reserved decision does not need to be made when it is
discovered — only before the work that depends on it finishes.** *(The exception: a decision blocking an
in-flight pass, which should be raised immediately and separately.)*

# 8. Path 7 — Developer creative elicitation

**The developer imaginatively places themselves into the subject and produces genuinely new content.** In this
project's own history this is the **City Vision Notes** process — pipeline steps 4 and 5 of the nine-step city
pipeline — and it is, measurably, **the single most productive acquisition mode the project has ever run.**

**What it produced, across ~35 cities in a matter of days:** the fabrication-synthesis chamber mechanism (the
first established account of how robot creation physically works); Mawson's identity as the honeymoon
destination for human-robot couples; Casey's Splinters bar; Byrd's underground scale; Dome Fuji's devotional
character; Zukelli's "place with a soul." **No research or derivation path could have produced any of these.**

**When it is right:** the gap is *characterological* — what a place or person is *like* — rather than factual.
**These gaps are frequently unanswerable by every other path**, and routing them to research instead produces
exactly the generic, plausible, characterless material the project's own depth law exists to prevent.

**Procedure** *(from the established Vision Notes practice)*:
1. **Present the subject's established facts first** — census, geography, function, what is already fixed.
   Elicitation without grounding produces content that contradicts canon.
2. **Ask open, not leading, questions.** The developer's answer is the acquisition; a leading question
   contaminates it with the asker's own guess.
3. **Record verbatim**, in the subject's own dedicated notes file, before folding anything anywhere.
4. **Then fold into canon — and this is the step that failed in 2026-07-05 (`00` LAW B).**

> ### ⚠⚠ THIS PATH'S OUTPUT IS ALMOST ALWAYS CONCLUSION-TIER. THIS IS WHERE THE FOUNDING FAILURE HAPPENED.
>
> **Everything Path 7 produces — a civic character, a pace of life, an aesthetic, a temperament — is exactly
> the class of content that a cold synthesis pass must treat as inadmissible.** Depositing it into an
> attribute-tier file (`Specs/`) is what broke a location pass eight weeks later, and it will do so again
> unless `03`'s deposit discipline is followed literally.
>
> **This is not an argument against Path 7.** It is the most valuable path in the system. **It is an argument
> that Path 7's output must be deposited with its kind marked**, so that the next cold pass can exclude it
> mechanically instead of discovering it by accident.

# 9. When no path fits

**Record the gap as `UNRESOLVED — no viable path`, with the paths considered and why each failed.** Do not
force a poor fit — a research path applied to a characterological gap produces generic filler, and a derivation
applied to a qualitative question produces a number that answers nothing.

**An honestly unresolved gap is a real output.** It tells the next session exactly where the frontier is.
