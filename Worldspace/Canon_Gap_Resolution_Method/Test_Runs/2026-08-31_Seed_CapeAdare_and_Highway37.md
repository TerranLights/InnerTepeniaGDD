# Test Run — Cape Adare & Highway 37 seed *(instance, NOT the method)*

> ## ⚠ THIS IS A TEST-RUN INSTANCE. IT IS NOT THE GAP REGISTRY, AND IT IS NOT THE METHOD.
>
> **Developer instruction, 2026-08-31, given during this system's own build:** *"it's extremely important to
> distinguish between the overall 'gap registry' and 'missing data synthesis' as being one thing, and using
> Cape Adare as a 'test run' instance as a separate thing. That way, Cape Adare running as a test case won't
> corrupt the overall synthesis methodology itself."*
>
> **Why this separation is real and not bookkeeping.** Cape Adare is the case that produced the realization
> this system was needed at all — which makes it exactly the case most likely to quietly shape the system
> around its own idiosyncrasies. **This project has already paid that price once**: the location methodology's
> first test run was a three-city co-write, and it produced *"a methodology validated on the least
> representative configuration in the project"* because nothing in the procedure asked whether the test case
> was typical.
>
> **The separation, concretely:**
> - **The method** (`00`–`04`) is scope-agnostic and must stay that way. It may cite Cape Adare as a **recorded
>   failure that grounds a rule** — that is legitimate and is how every rule in this project earns its
>   authority — but it must never be *shaped* by Cape Adare's particular gap list.
> - **This file** is one instance's data. **Nothing here generalizes.** Ratios, path distributions, and triage
>   splits found here are properties of these two scopes, not of the system.
> - **A future cold pass on Cape Adare must treat this file as inadmissible**, exactly as it would any other
>   completed pass's conclusions. Registered in the location methodology's own provenance manifest.

> 4 LIVE + 3 RESERVED = 7. Totals: 14 / 4 / 18.)*

**Two observations, both properties of THIS instance and neither generalizable to the method:**

1. **Zero SCHEDULED items, which is not the project-wide norm and is fully explained by the source.** Both
   scopes were seeded from ULM REQUESTED blocks — a synthesis pass emits a gap precisely *because* it wanted
   the answer now, so by construction its output skews LIVE. **A scope seeded by a TBD sweep would look
   completely different**, since the dominant project-wide pattern is scheduled deferral (`01` §4.1).
   **This is exactly the kind of ratio that must not be read back into the method.**
2. **Path 1 (cross-reference) is the first-choice path for 6 of 14 LIVE items.** Healthy shape — the cheapest
   path should dominate, and a queue where expensive paths dominated would suggest gaps being escalated before
   the cheap checks were run. **Also instance-specific**, and for a knowable reason: both scopes are
   well-connected locations with many sibling files to cross-reference against. A character scope, or an
   isolated location, would not produce this distribution.
