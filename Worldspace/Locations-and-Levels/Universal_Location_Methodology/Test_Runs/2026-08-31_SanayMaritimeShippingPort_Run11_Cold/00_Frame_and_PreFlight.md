## 6. ⚠ Self-correction, caught during Phase 1 — Band 0 is the wrong procedure for an ACTIVE Installation

**What I believed:** that declaring Population band 0 ("Uninhabited") was the correct, complete classification
for a location nobody resides at, and that this pass should therefore run under `01` §2.4's Band 0 procedure
(Surviving Witness promoted to primary instrument, content written in past tense, "who is here temporarily"
replacing "what do residents do daily").

**Why it was wrong.** `01` §2.4's Band 0 procedure is written for a *ruin* — its own framing throughout is
building stock, tool wear, a route people avoid, an inventory that doesn't balance: **testimony left behind by
people no longer there.** The port is not that. It is an actively operating Installation with continuously
present rotating dock crews, exactly matching `01` §1.1's own defining property of the Installation type —
"staffed rather than settled." A staffed-but-unsettled location is not the same condition as an unstaffed one,
and treating them identically collapses a real distinction the Type declaration itself already draws.

**What changed it.** Beginning Phase 1's population/extent density check (`02` §5.1 point 6) surfaced the
mismatch directly: dividing a WORKING population by extent produces a meaningful density figure; dividing zero
residents by extent produces a meaningless zero that says nothing about the location, and running the
Band-0-mandated Surviving Witness technique on an active site would have manufactured a "ruin" reading of a
place that isn't one — precisely LAW 0's anti-pattern of "accepting the first coherent answer because it fits
and the pass is long."

**The correction adopted:** declare 0 for RESIDENCY specifically (accurate, and the honest scope-artifact
noted in §1 above still applies), but run Phase-level PROCEDURE at Band-1-equivalent — named-individual-scale
analysis per `01` §2.3's Band 1 substitute rule ("four of them do this, two do that, and one refuses" — the
variance across named individuals IS the culture) — rather than the Band 0 ruin procedure. This is a genuinely
new methodological case: **every prior Band declaration in this project's ULM runs has treated "0 residents"
and "Band 0 procedure" as the same fact.** They are not. A location can have zero *residents* and a
substantial, continuously-present *working* population, and the procedure that fits is determined by the
latter, not the former.

**Logged as M-84** in `Test_Runs/OBSERVATIONS_and_Methodology_Findings.md`, flagging `01` §2 for a possible
future addition: a named case for "staffed, unsettled, non-ruined" locations, distinct from both Band 0
(ruin/testimony) and Band 1 (a dozen residents who live there). Not implemented into the rule file this
session — flagged for developer review rather than forced in, since it may affect how Mountain Pass Airport's
own Run 10 (which left its population/staffing model REQUESTED rather than declared) should be read
retroactively.
