## 3a. FIRST: run the INBOUND readiness check on yourself

**`00_RUNBOOK.md` Step 10 is a standing step, and it has two directions.** The outbound half runs at the *end*
of a pass, by whoever hands off. **The inbound half is yours, and it runs now, before you read anything else
about the chosen location:**

   subnet, a cluster, a parent). Every hit must be **attribute-only** or **banner-warned**. **If an un-banded
   entry states the location's character, temperament, personality triple, or a signature phrase — stop

2. **Check `06_Worked_Example_Provenance.md`** for whether the chosen location carries any manifested worked
   examples in `00`–`05`/`00f` — unlikely for a genuinely new subject, but check by name rather than assuming.
3. **Open the header of every file you are about to treat as admissible**, and check its own cited sources.
   **A file that cites a withheld or conclusion-bearing document is downstream of it, whatever its filename
   says.**
4. **Confirm the location's own canon files actually exist where the registry (`00_RUNBOOK.md` §B–D) says they
   should**, rather than assuming a standard file layout — some location types will not have a `Local_Cultures`
   sheet, an Enneagram read, or a Megasheet folder at all, and that absence is itself an input (a REQUESTED-
   input case, per `05` §5), not a gap to paper over.

**Record what the inbound check finds, including "nothing."** A clean check is evidence; an unrun one is not.

## 3b. The general admissibility rule, applied fresh to whatever the chosen location has

Per `05` §6.1's operational split:

- **ADMISSIBLE:** physical/environmental facts, founding mechanism/date/circumstance, function/industry,
  network position/routes, census/composition/population-change, dated events, a research log (if one exists
  for this location — it holds attributes, never conclusions, per `05` §6.1).
- **INADMISSIBLE:** any prior culture-pass conclusion about the location — character, temperament, capability
  profile, shape, axis, or differentiation claim — however it is phrased and whatever file it lives in.
- **⚠ Admissibility is a property of content, never of filename or folder** (`05` §6.1a). **A file is
  admissible only if every section of it is.** Check headers for cited sources before trusting a file's name.
- **⚠ Row-level mixing** (one admissible column, one inadmissible column, in the same table — e.g., a symbol
  assignment's *members* vs. its derived *rationale*) needs a column-anchored search pattern, not a bare-name
  search, or the inadmissible field leaks through (`05` §6.1a's own worked note).

## 3c. Navigate by path, never by query

**This repo enforces a `PreToolUse` hook requiring `graphify query` before file reads, and `CLAUDE.md` repeats
it.** **A graph query naming the chosen location returns extracts from whatever culture-pass conclusions exist
for it** — retrieval indexes content, and quarantine is a property of provenance, which a corpus-wide index
cannot honor. **Use `find`/`ls` to locate files and direct reads to what is confirmed admissible. Declare this
violation of the tooling convention deliberately, in the observations log** — the circularity rule outranks a
search convention.

## 3d. When you must EDIT a file you may not READ

**It will happen** — a developer ruling, a typo, a canon fix landing on an inadmissible file. **Do not read it,
and do not defer it.**

> **Locate by `grep` (shows one line) · patch by exact-match script with `assert count == 1` (shows none) ·
> verify by `grep` (shows one line).** Three narrow windows instead of one open door. Where the match itself
> would expose inadmissible content on the same line (a mixed table row), anchor the search pattern to only
> the fields you need — see §3b.

## 3e. If a per-location research log exists

**Check `Cities/Research_Logs/` (or the equivalent folder for the location's own type) for a dedicated log
before assuming none exists.** A research log records exact search strings, sources, a fact→finding table, what
was withheld vs. omitted, divergences from source, and open threads — **it holds attributes, never
conclusions, so it stays admissible even to a cold run**, and open threads are frequently the highest-value
unpursued material available. If none exists for the chosen location, create one at Step 3 of the task below,
per `00_RUNBOOK.md` §3.7.
