## ⚠ The one thing to know before anything else: this is NOT a virgin location like Mountain Pass Airport

Run 10 (Mountain Pass Airport) tested quarantine discipline on a location with **zero** prior culture-pass
material anywhere. **The Sanay Shipyard is the opposite case**: it is a sub-location inside a fully
developed outer city (Sanay) that has already been through a complete 32-section `Local_Cultures` pass, a
`Local_Robot_Culture` pass, an Enneagram read, a Mega-Init/Full-Extrapolation/Cross-Reference-Synthesis
Megasheet sequence, and a dedicated Community Infrastructure pass — **several of which reach specific,
named conclusions about the shipyard itself**: the Shipyard Complex and the Trade Yard are both named
landmarks with stated character ("hit hardest, fixed first," a Guangzhou-Canton-System bounded-contact
zone), the port's rotating freighter-tied work rhythm is fully described, "function over sentiment" is
established as a defended civic value with a stated unequal cost, and — most consequentially — a proposed
(non-canon, unratified) origin incident for the entire project's Human-Robot Relations Baseline is set at
this specific dockside.

**This makes the Sanay Shipyard structurally closer to a Zhongshan/Sinheung-style re-run (a location with
deep prior conclusions requiring rigorous quarantine) than to a Mountain-Pass-Airport-style virgin case** —
except the *prior pass* was never about "the shipyard" as its own declared location; it was about Sanay as
a whole, with the shipyard as one part. **Whoever runs this should record that distinction explicitly as
part of the Frame Declaration's own Configuration note** — it is a genuinely new methodological case this
project's ULM test-run series has not produced before: a first-ever pass on a *named sub-location*, whose
*parent* already has a complete culture pass reaching real conclusions about that exact sub-location.

## Type and Position implications worth declaring up front

**Type**: almost certainly **Installation** (purpose-built for a function, controlling institution, staffed
rather than settled) — same primary Type as Mountain Pass Airport (Run 10), making this a **third**
Installation-type data point if run, not new-Type coverage. State this explicitly in the Frame Declaration,
per the standing practice.

**Position — Parent is real and singular, unlike Mountain Pass Airport's dual/absent parent.** Sanay is a
fully developed, single-founder Settlement. This means the shipyard's own Determined properties (currency,
calendar, language family) have a real, specific, already-admissible source to draw from (German-Primary
demographic tier, per the census data above) rather than Mountain Pass Airport's own thinner subnet-level
inheritance. **A fresh session should expect a meaningfully different Inheritance-classification profile at
Gate I** — likely more Inflected material available (a real parent city to inflect national holidays,
language, etc. from) than Mountain Pass Airport had, which had almost none.

**The methodological question worth stating explicitly, per the developer's own standing instruction to
record snags rather than route around them:** does a location whose *parent* has already reached
conclusions about it get a genuinely fair cold test, even with perfect quarantine discipline? The shipyard
itself has never been separately run — but the questions this methodology's own generators would ask about
it (what is its function, its founding condition, its network position) have all already been answered, in
detail, for the parent's own sake. A fresh session should watch specifically for whether its own "cold"
findings suspiciously converge with the quarantined material's own shape even when never having read it —
convergence here would be **weaker evidence of anything** than Sinheung Run 5's own convergence with its
withheld culture sheet, precisely because the generator inputs (founding condition, function, physical
facts) are shared with the parent's own material by construction, not independently arrived at.
