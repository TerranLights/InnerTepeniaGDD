# Shirayuki — manual input audit (2026-10-30) — a FINISHED city: drift since the pass

Method: `README.md` in this folder. **Shirayuki's ULM pass was run and closed on 2026-09-06** (23 files in the pass folder, about 660 KB; last substantive change 2026-10-01, "apply the audit fixes"). It has **no Pre-Trip and no datasheets**, so there is no Part A: the question is only *has anything the finished pass rested on changed since?* **Finished pass files are never edited**: each drift item is an `AMEND` entry in `FIX_LEDGER.md` (entries `SRY-…`). **Limit, stated plainly:** the pass files were *not* re-read line by line (about 660 KB, 200 KB of it the log); `00_Frame.md`, `09_Record.md`, the workforce and Phase 5 passages were read, and drift was found by (1) `git` history of the spec, read as a diff between the pass-time version (commit `5c339aee`, 2026-09-06) and now, (2) counting the old values and old names inside the pass files, (3) comparing what the pass recorded with the live shared files. `LOC` = `Worldspace/Locations-and-Levels/Outside-World/Tepenian-Federation/Locations`, `CITIES` = `LOC/Cities`. Pass folder: `CITIES/City_Development_Passes/Mirny_Subnet/Shirayuki/`.

**Verdict.** **The pass is not harmed in its method**, and it already handled the one earlier population change correctly (the −10% cut of 2026-09-05: it carries both the pre-cut `890,078` and the post-cut `~801,070` workforce). What has moved since is **census-driven (the 2026-10-28 scenario, `DR-68`)** and **renames**: the pass records the pre-`DR-68` counts and every figure derived from them, and four retired names. Two source problems the pass could not know: the census Section A tier list for the city is still the old China-Primary one, and `16` §16 still carries counts on the pre-cut workforce. Nothing in the pass is *wrong when written*; one passage cites a source line it does not match.
